**사전 예측이 틀렸고 결론은 더 강하다.** "PV가 크면 잉여 PV로 충전해 비구속"일 것으로 봤으나,

**"PV 덕분에 맞물린다"가 아니라 "ESS가 캠퍼스 규모 대비 작아 어떤 설비 구성에서도 제약이 되지
않는다"**다.

**실질 부담은 요금이 아니라 배터리 사이클**: G_s +56%, EFC 177→277회/년. 다만 그 경우에도
사이클 기준 수명 18.1년 > calendar 10년이라 "수명은 경과시간이 결정" 결론은 유지된다.

⚠ **조원 모델에서 재확인 필요** — 그쪽 최적 ESS는 6,778kWh로 여기의 15.8배다. 의무충전 비용은
ESS 용량에 거의 비례하므로 0.02% → **약 0.3%**(순절감 19.4억 대비 약 0.46억/년, 2.4%)까지 커질
수 있다. 결론을 뒤집을 크기는 아니나 보고서 수치로는 넣어야 한다. EFC 증가율(+56%)은 용량에
무관한 비율이라 그대로 적용된다.

## 2. 코드 수정 항목

### 수정 완료

**SOC 동역학 시간 인덱스** (2026-11-05, 외부 검토 지적) — 실제 버그였고 LP가 악용하고 있었다.
동역학 제약이 `for t in range(1, T)`라서 `P_ch[0]`/`P_dis[0]`이 어떤 에너지수지 식에도 등장하지
않고, `E[0]`은 bounds로 e0에 고정돼 있어 LP가 **SOC를 바꾸지 않고 PCS 최대치로 방전**했다.

```
수정 전:  P_dis = [142.7, 0, 0, ...]   E = [214, 214, 214, ...]  ← SOC 불변
          t=0 에너지수지 미반영분 = +39.16 kWh/년 (공짜 에너지)
수정 후:  P_dis = [0, 0, 0, ...]       미반영분 = 0.00 kWh
```

→ `E`를 **T+1개 상태변수**(E[0]~E[T], 양 끝 e0 고정)로 바꾸고 동역학을
`E[k] = E[k-1] + η_ch·Δt·P_ch[k-1] − Δt/η_dis·P_dis[k-1]`, k=1..T로 수정.
금액 영향은 연 7천원 수준으로 총비용 결론은 불변이지만(당시 기준),
Rainflow 괴리율이 -0.46% → **-0.43%**로 갱신됐다(허수 방전이 throughput에서 제거됨).

**`D_s` 기본요금 ×12** — 팀원 지적이 맞고, 내 코드 버그였다.
6,980원/kW는 **월** 단가(교육용(을) 고압A)인데 다른 항(전력량·탄소·열화·PV)은 전부 연간이었다.

```
기본요금 ×1  =  1.43 억원/년   ← 수정 전
기본요금 ×12 = 17.14 억원/년   ← 수정 후 (설치 전 피크 20,458kW 기준)
누락액       = 15.71 억원/년
```

→ `ess_pv_pipeline.ipynb` 4-1에 `PEAK_MONTHS = 12` 추가, 4-2의 `c[idx_peak]`·`D_s` 반영. 27개 조합 재실행.

### 역할 분담 (제안)

- **`ess_pv_pipeline.ipynb`** = 연구 기여 담당. 기후 시나리오 부하 생성(1단계) · PV 물리(2단계) ·

### DPNN의 위치 — **벤치마크로 가져다 고정한다** (2026-11-05 정정)

**논문**: Liu, Zhao & He (2026), "Economic emission dispatching strategy considering dynamic
parameter effects: A novel approach based on projection neural networks and deep learning",
*Energy Economics* 154, 109104. (`University/융합연구학점2/1-s2.0-S014098832500934X-main.pdf`)

- **문제**: Economic Emission Dispatch — 목적함수가 발전비용 + **배출비용**(우리 `E_s`+`K_s` 구조)
- **동기**: EED는 dynamic parameter(전력수요, RES 발전에 영향 주는 기후인자)에 지배되는데
  기존 solver는 파라미터가 바뀌면 매번 반복 재계산해야 해서 느리다
- **DPNN**: Projection Neural Network를 딥러닝에 임베딩 → dynamic parameter를 입력받아
  **반복 없이 해를 즉시 출력**. 학습이 **unsupervised(PNN-guided)** 라 미리 풀어둔 해
  데이터셋이 필요 없다(구현 부담이 작다)

**기여 구조**: DPNN을 개발하는 게 아니라 **벤치마크로 고정**하고, "왜 학교를 봐야 하는가"를
보이는 것. 교수님 연구계획서 3절의 *"기존 연구의 검증된 최적화 모델을 benchmark로 선정하여
고정하고, 수요환경(AI workload 침투율, 폭염 강도)을 체계적으로 변화시킨다"*가 바로 이것이다.
→ README의 *"신규 최적화 알고리즘 개발이 아님"*은 DPNN 배제가 아니라, **DPNN을 우리가 만들지
않고 가져다 쓰는 것이 조건에 맞는다**는 뜻이다(2026-11-05 이전 기록은 이를 반대로 해석했음).

**논문의 공백 = 우리 기여**: 논문 검증은 **발전기 10기 합성 테스트케이스**에서 추상적 파라미터
인스턴스(φ₅, φ₆)로만 이뤄진다. dynamic parameter가 실제로 크고 결과가 중대한 사례가 없다.
캠퍼스는 (a) AI 인프라로 파라미터가 **regime shift**를 겪고, (b) 결과가 구체적이며(계약전력
피크 1회 → 12개월 요금, 냉방·배터리 조기 소모), (c) 그 파라미터 공간을 우리가 이미 실측
기반으로 보유(회귀모형 + SSP 4종 × 2시기). **논문은 "빠르다"를 증명했고 우리는 "이 문제가
실제로 중대하다"를 증명하는 사례가 된다.**

**형태 매핑 결정: (b) 확정 (2026-11-05).** 타당성 검토 결과 (b)는 선택이 아니라 **필수**였다 —
PNN은 "선형 등식 + 박스 제약"만 풀 수 있고 우리 기본요금 항(epigraph 부등식)은 그 형태에
들어가지 않는다. (b)로 가면 `P_peak`가 MPC가 내려주는 파라미터가 되어 그 제약이 `P_grid,t`의
박스 상한으로 전환된다. 상세 근거·설계·다음 단계는 **`reference/dpnn_feasibility.md`** 참고.

### 기술적 위험 — 문제 형태 불일치 (해결됨, 아래는 경위 기록)

논문의 EED는 **시점별 static convex** 문제다(`multi-period` 0회, `ramp` 0회, `SOC` 3회;
비용함수 $C_i(P_{Gi,t})=a_iP^2+b_iP+c_i$ = 매 시점 발전기 출력 배분). 그래서 "파라미터가
바뀌면 즉시 재해"가 장점이 된다.

우리 LP는 **SOC 시간결합**($E_t=E_{t-1}+\dots$)과 **기본요금**($P_{peak}\ge P_{grid,t}$, 전 구간
max)이 모든 시점을 묶어 시점별 분해가 불가능하다. 둘 중 하나를 선택해야 한다.

| 방식 | 내용 | 평가 |
| --- | --- | --- |
| (a) 호라이즌 통째로 | 24~48h(96~192구간) 전체 해벡터를 DPNN이 출력 | 논문에 충실하나 차원이 큼 |
| (b) **초단기 보정 계층에 배치** | SOC를 **상태 파라미터로 입력**받아 해당 시점 보정량 출력 | **논문 구조와 일치**, 연구안 4.3에 그대로 들어감 |

**(b) 권장.** 연구안 4.3이 이미 *단기 MPC(24~48h 계획) + 초단기 실시간 보정 + receding horizon*
2계층이므로, SOC를 파라미터로 넘기면 초단기 계층이 논문의 static 문제 형태가 되고 DPNN의
"반복 없는 즉시 응답"이 제자리를 찾는다. **MPC는 DPNN의 대안이 아니라 DPNN이 들어가 앉을
자리**이다. (2026-11-06 보정: 당초 여기에 "예측기가 그 위에 입력을 공급"한다고 썼으나, 예측기를
두지 않는 반응형 구조로 재정의됐다 — 아래 Phase 4 참고.)

| 설비 축(UCSD)·일본 축(기타큐슈) | 선택 — 외적 타당성 검증용. 필수 아님 |

**이 결정이 만드는 두 가지 귀결 (논문에 반드시 반영)**

1. **검증 전략이 제한된다.** 교내 ESS·PV 운영 실측이 없으므로 디스패치 결과를 실측과 대조할 수
   없다. 검증은 ① 부하모형 ↔ 한전 청구서 대조, ② LP/DPNN 구현 ↔ PNN·convex solver 해 일치,
   ③ 설비 파라미터 ↔ **민감도 분석**의 세 축으로만 가능하다.
   → 지도교수 자문("문헌값 편차가 큰 항목은 민감도 분석에 활용")의 비중이 그만큼 커진다.
   이것을 **연구 한계**로 명시할 것.
2. **"기존 EMS" 표현을 쓰면 안 된다.** 연구안 배경·목표가 *"기존 캠퍼스 EMS의 운영 한계 검증"*,
   *"이미 충분히 최적화된 기존 EMS"*로 서술돼 있으나, 실제로는 교내 EMS가 없으므로 정확한 표현은
   **"문헌에서 검증된 모델(DPNN)로 구성한 벤치마크 EMS"**다. 이 구분을 흐리면 심사에서 지적된다.
   README 1·3절과 보고서 문구를 이 기준으로 손볼 필요가 있다.
